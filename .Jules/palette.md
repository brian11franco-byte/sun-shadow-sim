## 2026-07-05 - Custom HTML Switch Semantics and Focus Visibility

**Learning:** Custom button-based toggle switches in HUD or glassmorphism control panels often visually reflect state through CSS classes (e.g. `.on`) while missing standard ARIA switch semantics (`role="switch"`, `aria-checked="true|false"`). Without explicit `aria-checked` and dynamic context in `aria-label`, screen readers announce them only as generic static buttons without conveying whether the item is enabled or disabled. In addition, dark glassmorphism interfaces often lack visible focus indicators (`:focus-visible`) for custom toggle pills, hindering keyboard navigation.
**Action:** When implementing or styling toggle switches, always equip `<button>` elements with `role="switch"`, initialize `aria-checked`, dynamically synchronize `aria-checked` and contextual labels upon interaction, and provide a high-contrast `:focus-visible` ring using existing brand or accent tokens (e.g., `outline: 2px solid var(--sun)`).
